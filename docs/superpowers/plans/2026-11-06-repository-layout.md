# Repository Layout Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan
> inline. The owner approved the directory design and requested implementation.

**Goal:** Separate services, deployment, tests and operator tooling without
changing VPN or API behavior.

**Architecture:** Move current components intact; update path consumers together.
Keep service-specific contracts beside the Python service and cross-service
scenarios at the root. A thin CLI dispatches existing implementations.

**Tech Stack:** Python 3.11+, Bash, Docker Compose, uv, Ruff, basedpyright.

**Spec:** `docs/repository-layout.md`.

## Global Constraints

- No production changes, publishing, main/dev integration or worktrees.
- Preserve unrelated untracked `scripts/update_tailscale.sh` unchanged.
- Do not refactor `src` internals; preserve runtime configuration semantics.
- Use a feature branch, retaining the current runtime-reconciliation ancestry.
- Private configuration and generated evidence remain ignored.

## Review Focus

- Compose invoked outside the checkout must retain root input and volume paths.
- Bootstrap must work when Python/the checkout are not installed yet.
- Update rollback must survive transitions between old and new directory layouts.
- Remote source bundles must contain every dependency at the expected path.
- CLI help/list/invalid commands must never trigger mutations or network work.
